# ADR 0007: 全局翻译与润色工作模型

## Status

Accepted

翻译与润色的输入和输出属于可授权访问的规范资源，而不是发起请求的用户。系统采用由调度器持有的 admission/retry 事务与 worker 唯一写入边界管理全局工作项、尝试和结果投影；用户只保留请求关联与访问控制。旧的用户隔离表和缓存保持原样，作为不可变历史证据。切换使用扩展表与兼容版本，而不重命名、删除或重建旧表，避免丢失历史并为应用回滚保留可启动的数据库边界。

## Considered Options

- 继续按用户创建工作项和缓存：拒绝。相同资源会重复调用模型，并让管理页在不同用户的局部事实之间产生相互矛盾的状态。
- 把旧表直接改名或重建为全局表：拒绝。它会破坏旧二进制对迁移版本和表结构的预期，也会把历史事实与当前状态混在一起。
- 在新旧模型之间长期双写：拒绝。两个写入者无法形成单一的状态和重试事实。

## Consequences

- “翻译”和“润色”保持既有功能名称；内部 `release_smart` 等标识不决定产品文案。
- 新模型不从旧缓存或旧工作项伪造当前工作状态、尝试次数或全局结果。旧事实以 `legacy_cached` 或 `legacy_conflict` 来源状态展示。
- 数据库迁移只能追加新表、索引和控制记录。旧表及其历史行不在本主题中更新、删除、改名或回填。
- 预切换兼容版本必须先部署并应用扩展迁移；切换版本不能再引入数据库迁移。迁移后不能回滚到不含该迁移版本的旧二进制，因为 SQLx 会拒绝未知的已应用迁移。兼容版本是可回滚的最低版本，并在发现全局模式时停止旧写入者。
