# ADR 0013: 管理采集记录按查询键合并在途读取

## Status

Accepted

## Context

管理采集记录读取已按来源时间索引限界候选集，但并发到达的相同查询仍会重复执行数据库工作。全局并发闸门会让不同筛选条件互相拒绝，而完成结果缓存会把过期状态伪装为当前事实。

## Decision

- 列表与活动概览各自使用独立的 keyed singleflight；查询键覆盖端点和全部规范化查询条件。
- 同键在途请求共享一次读取，不同键独立执行；读取完成后不缓存响应。
- 共享读取任务无论正常完成、超时或 panic，都必须向等待者发布完整结果或错误并释放查询键，使后续重试可重新执行。调用者取消等待不取消共享读取。
- 仍保留五秒源站安全预算、精确总数与完整失败语义；不返回部分数据。

## Supersession

本决策仅取代 ADR 0009 中拒绝合并在途读取的选项。ADR 0009 的查询窗口、精确总数、有界候选查询和超时约束继续有效。

## Considered Options

- 每个并发请求都独立读取：拒绝。同一查询的突发请求会重复消耗数据库读取容量。
- 缓存已完成的响应：拒绝。管理员需要读取当前事实，完成结果缓存会隐藏后续状态变化。
- 使用全局读取闸门合并或限制请求：拒绝。不同键的查询不应互相阻塞或返回忙碌错误。

## Consequences

- 相同查询的并发读取合并为一次数据库执行，筛选不同的读取保持独立。
- panic 会作为完整内部错误返回；共享键被释放，后续同键请求可以恢复读取。
- singleflight 是进程内的在途请求协调，不构成跨实例去重或结果缓存。
