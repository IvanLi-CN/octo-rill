# ADR 0002: Dashboard 可读区块分页

## Status

Accepted

## Context

Dashboard 根页的原始活动 cursor 按单条记录推进，而历史记录可以被日报折叠。客户端根据 DOM 投影暂停或继续原始 cursor，既无法保证下一页有新的可读内容，也会在已成功取得数据时把用户留在列表末尾。直接预取所有原始活动又会把发布正文、翻译和互动数据带入日报优先的阅读路径。

## Decision

- 非 scoped 的 Dashboard `全部` tab 使用服务端拥有的可读区块序列；区块 cursor 以完整区块的时间边界推进，而不是以前端渲染投影决定是否继续。
- 每个主分页响应最多交付三个完整可读区块。历史日报区块直接携带完整日报正文与未被日报覆盖的补充动态；它不得以摘要或正文占位符替代。
- 历史日报的完整原始活动集合仅在用户选择“列表”后，通过区块受限的明细 cursor 按需取得。没有日报的历史区块默认是原始活动区块，并保留用户显式生成日报的入口。
- `/api/feed` 继续是原始动态、筛选与 scoped 阅读的兼容接口。普通同步和日报生成不使已发出的可读区块 cursor 失效；日界设置变更或显式刷新由前端重新开始区块序列。

## Consequences

Dashboard 根页不再依赖“已加载的原始记录恰好足够构成日报组”这一隐式条件，且不再显示“继续加载历史动态”作为正常分页路径。服务端需要维护可按用户和时间边界检索的区块读模型，并保证日报覆盖关系、补充动态和区块明细由同一边界定义。日报 tab、侧栏和通用 raw feed 可以在不改变既有 HTTP 合同的情况下独立演进。
