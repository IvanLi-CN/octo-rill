# ADR 0011: 无感持久化状态迁移

## Status

Accepted

OctoRill 的 durable state 演进必须保持用户可见的内容处理路径连续：迁移不得以 `rollback_freeze` 或其他迁移专属 `503` 拒绝原本有效的提交，已发布的结果投影持续可读，已接受的工作保持可恢复。结构变更、当前数据操作和历史数据回填分别执行并独立观察、暂停与恢复；每项已部署迁移不可逆转，故障由可识别现存状态的 forward repair 处理。

这项决定取代 ADR 0007 中受控冻结的切换行为。ADR 0007 的全局工作身份、旧事实保留和不允许长期双写的边界继续有效。迁移期间的唯一写入者必须通过兼容的 admission 与状态转换持续接收工作，而不是关闭提交路径。

## Consequences

- 迁移中的有效提交继续写入可兼容的持久化工作与请求者关联；客户端只观察既有的排队、执行、结果或可重试状态。
- DDL 只允许扩展性变更；破坏性清理在兼容窗口结束后的独立 release 进行。
- 历史回填使用可恢复 cursor、批次进度和前台写压力让行；暂停回填不改变用户提交或读取语义。
- 每项迁移必须记录受支持的 source state、操作顺序、观测信号、暂停点、forward-repair 路径与跨版本验证证据。
